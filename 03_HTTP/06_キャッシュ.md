# 第3章-06：キャッシュ

---

## 1. キャッシュとは

キャッシュ（Cache）は、一度取得したリソースのコピーを保存しておき、
**次回からサーバーに問い合わせずにコピーを返す** 仕組みです。

```
キャッシュなし:
クライアント → リクエスト → サーバー → レスポンス → クライアント
（毎回サーバーとやり取り）

キャッシュあり:
クライアント → キャッシュが保存済み → キャッシュから返す
（サーバーへの通信不要）
```

---

## 2. キャッシュのメリット

### パフォーマンスの向上

ネットワーク通信を省略できるため、レスポンスが格段に速くなります。

```
サーバーからの取得: 200ms
キャッシュから取得: 5ms

→ 40倍速い
```

### サーバー負荷の軽減

同じリクエストを何万ものユーザーが送っても、
キャッシュがあればサーバーへのリクエストが大幅に減ります。

### 帯域幅の節約

特に大きな画像や動画では、キャッシュによる転送量削減が大きい。

---

## 3. キャッシュの種類

### ブラウザキャッシュ（プライベートキャッシュ）

ブラウザが個人のコンピューターに保存するキャッシュです。
そのユーザーのリクエストにのみ使われます。

```
ブラウザ → ブラウザキャッシュ → サーバー
              ↑個人用キャッシュ
```

### プロキシキャッシュ（共有キャッシュ）

会社や ISP のプロキシサーバーが複数ユーザー分をキャッシュします。

```
ユーザーA  ┐
ユーザーB  ├→ プロキシキャッシュ → サーバー
ユーザーC  ┘
```

### CDN（Content Delivery Network）

世界中に分散したサーバーにキャッシュを置き、
ユーザーに最も近いサーバーからコンテンツを返します。

```
日本のユーザー → CDN（東京）→ キャッシュがあればそこから返す
                             キャッシュがなければオリジンサーバーから取得
```

---

## 4. Cache-Control ヘッダー

キャッシュの振る舞いを制御する主要なヘッダーです。

### max-age

キャッシュを有効な秒数を指定します。

```http
Cache-Control: max-age=3600
```

この場合、3600秒（1時間）はサーバーに確認せずキャッシュから返します。

### no-cache

キャッシュしてよいが、**使う前にサーバーに有効性を確認（再検証）** することを指示します。
「キャッシュするな」ではなく「使う前に確認しろ」という意味です。

```http
Cache-Control: no-cache
```

### no-store

**一切キャッシュしない** ことを指示します。
銀行の取引履歴など、機密性の高いデータに使います。

```http
Cache-Control: no-store
```

### public / private

```http
Cache-Control: public    → CDN など共有キャッシュに保存してよい
Cache-Control: private   → ブラウザ（個人）のみキャッシュ可。CDN は不可
```

ログイン後のユーザー固有のページは `private` にすべきです。

### s-maxage

CDN など共有キャッシュでの有効時間を指定します（`max-age` は上書きされる）。

```http
Cache-Control: max-age=3600, s-maxage=86400
```

ブラウザキャッシュは1時間、CDN は24時間という設定です。

### must-revalidate

キャッシュが期限切れになったら、必ずサーバーに確認することを要求します。

```http
Cache-Control: max-age=3600, must-revalidate
```

### immutable

このリソースは有効期間中に **絶対に変更されない** ことを示します。
リロード時も再検証を行いません。
JS・CSS をハッシュ付きファイル名で配信する際に使われます。

```http
Cache-Control: max-age=31536000, immutable
```

---

## 5. 条件付きリクエスト（Conditional Request）

キャッシュが期限切れになったとき、**変更がなければキャッシュを使い続ける** 仕組みです。
完全な再取得を避けることで、帯域幅を節約できます。

### ETag を使った方法

#### 最初のリクエスト

```http
→ GET /logo.png HTTP/1.1

← HTTP/1.1 200 OK
   ETag: "abc123def456"
   Cache-Control: no-cache

   [画像データ]
```

#### 次のリクエスト（キャッシュが期限切れ後）

```http
→ GET /logo.png HTTP/1.1
   If-None-Match: "abc123def456"   ← 前回の ETag を送る

（変更なしの場合）
← HTTP/1.1 304 Not Modified
   ETag: "abc123def456"
   （ボディなし → クライアントはキャッシュを使う）

（変更ありの場合）
← HTTP/1.1 200 OK
   ETag: "xyz789new000"
   [新しい画像データ]
```

### Last-Modified を使った方法

```http
← HTTP/1.1 200 OK
   Last-Modified: Mon, 20 Apr 2026 12:00:00 GMT

→ GET /logo.png HTTP/1.1
   If-Modified-Since: Mon, 20 Apr 2026 12:00:00 GMT

（変更なしの場合）
← HTTP/1.1 304 Not Modified

（変更ありの場合）
← HTTP/1.1 200 OK
   Last-Modified: Mon, 21 Apr 2026 10:00:00 GMT
   [新しいデータ]
```

### ETag vs Last-Modified

| | ETag | Last-Modified |
|-|------|--------------|
| 精度 | バイト単位で正確 | 1秒単位 |
| 仕組み | ハッシュやバージョン番号 | 日時文字列 |
| 推奨 | こちらが優先 | サポートが難しい場合の補完 |

---

## 6. キャッシュの設計指針

### 静的アセット（JS・CSS・画像）

コンテンツの内容が変わるたびにファイル名を変える（ハッシュを付ける）戦略が効果的です。

```
main.abc123.js   → キャッシュ有効期間を長く設定
logo.xyz789.png  → Cache-Control: max-age=31536000, immutable
```

ファイル内容が変われば URL が変わるので、古いキャッシュが使われる心配がありません。

### HTML ファイル

ページの入口となるファイルで、常に最新版を取得したい。

```http
Cache-Control: no-cache
```

または短い max-age を設定します。

### API レスポンス（動的データ）

ユーザー固有のデータは基本的にキャッシュしない。

```http
Cache-Control: no-store
```

公共データ（天気予報など）は短い期間でキャッシュしてよい。

```http
Cache-Control: public, max-age=300   （5分間キャッシュ）
```

---

## 7. キャッシュの注意点

### キャッシュの無効化が難しい

一度キャッシュされると、期限が切れるまで古いコンテンツが返り続けます。
「すぐに更新を反映させたい」という場合、ファイル名を変えることが必要です（キャッシュバスティング）。

```
古い: /js/app.js          → キャッシュされている
新しい: /js/app.abc123.js → 新しい URL なのでキャッシュなし
```

### プライバシーの考慮

ログイン後のページを `public` でキャッシュすると、
CDN が全ユーザーに同じキャッシュを返してしまい情報漏洩になります。

必ず `private` または `no-store` を設定してください。

---

## まとめ

| ディレクティブ | 意味 |
|-------------|------|
| `max-age=N` | N 秒間はキャッシュから返す |
| `no-cache` | 毎回サーバーに有効性を確認してから使う |
| `no-store` | 一切キャッシュしない |
| `public` | CDN など共有キャッシュに保存可 |
| `private` | ブラウザ（個人）のみキャッシュ可 |
| `immutable` | 有効期間中は絶対に変更されない |

条件付きリクエスト：
- `ETag` + `If-None-Match`：ハッシュでの一致確認
- `Last-Modified` + `If-Modified-Since`：日時での変更確認
- 変更なし → `304 Not Modified`（ボディなし、キャッシュ使用）
- 変更あり → `200 OK`（新しいデータ）
