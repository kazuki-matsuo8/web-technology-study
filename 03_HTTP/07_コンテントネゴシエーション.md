# 第3章-07：コンテントネゴシエーション

---

## 1. コンテントネゴシエーションとは

同じリソースでも、クライアントによって欲しい形式が異なります。

- ブラウザは HTML で表示したい
- iOS アプリは JSON でデータが欲しい
- 日本人ユーザーは日本語で見たい
- 海外ユーザーは英語で見たい

**コンテントネゴシエーション（Content Negotiation）** は、
クライアントとサーバーが **最適な表現形式を交渉して決める** 仕組みです。

URI は同じでも、クライアントの好みに合わせた表現を返します。

```
GET /users/42 HTTP/1.1
Accept: application/json   → JSON を返す

GET /users/42 HTTP/1.1
Accept: text/html          → HTML を返す

（どちらも同じ URI。クライアントの希望で形式が変わる）
```

---

## 2. コンテントネゴシエーションの種類

### サーバー駆動ネゴシエーション

クライアントが希望をヘッダーで送り、**サーバーが最適な表現を選んで返す** 方式です。
最も一般的な方式です。

```
クライアント → Accept: text/html, application/json
サーバー   → Content-Type: application/json（サーバーが決める）
```

### エージェント駆動ネゴシエーション

サーバーが選択肢を返し、**クライアントが選ぶ** 方式です。

```
クライアント → GET /data
サーバー   → 300 Multiple Choices
              （JSON / XML / HTML の URL リストを返す）
クライアント → 希望の URL を再度リクエスト
```

現実ではほぼ使われません。

### 透過的ネゴシエーション

プロキシがクライアントの代わりにネゴシエーションする方式です。

---

## 3. Accept ヘッダー：メディアタイプのネゴシエーション

クライアントが受け入れ可能なメディアタイプを示します。

```http
Accept: text/html,application/xhtml+xml,application/xml;q=0.9,*/*;q=0.8
```

### q 値（品質係数）

`q=` は優先度を表します（0〜1。デフォルトは 1.0）。

```http
Accept: text/html,                  → 最優先（q=1.0）
        application/json;q=0.9,     → 次に優先
        */*;q=0.1                   → どれでも（最低優先）
```

### サーバーの処理

サーバーは Accept ヘッダーを見て最も適切な形式を選びます。

```
Accept: application/json, text/html;q=0.5

→ JSON を返せるなら JSON
→ JSON は無理でも HTML を返せるなら HTML
→ どちらも無理なら 406 Not Acceptable
```

### 406 Not Acceptable

サーバーが Accept で指定された形式のいずれも返せない場合に返します。

---

## 4. Accept-Language：言語のネゴシエーション

クライアントが希望する言語を指定します。

```http
Accept-Language: ja,en-US;q=0.9,en;q=0.8
```

この例では：
1. 日本語（q=1.0）
2. アメリカ英語（q=0.9）
3. 英語全般（q=0.8）

の優先順で希望しています。

### サーバーの処理

```
Accept-Language: ja;q=1.0, en;q=0.5

→ 日本語コンテンツがあれば日本語で返す
→ 日本語がなければ英語で返す
→ どちらもなければデフォルト言語で返す
```

レスポンスには `Content-Language` ヘッダーで実際の言語を示します。

```http
HTTP/1.1 200 OK
Content-Language: ja
```

---

## 5. Accept-Encoding：圧縮形式のネゴシエーション

クライアントが対応している圧縮形式を指定します。

```http
Accept-Encoding: gzip, deflate, br
```

| 圧縮形式 | 説明 |
|---------|------|
| `gzip` | 最も普及している圧縮形式 |
| `deflate` | zlib 形式 |
| `br` | Brotli。gzip より高圧縮率。HTTPS 限定 |
| `identity` | 圧縮なし |
| `*` | どれでも |

### 圧縮の効果

テキストデータ（HTML・JSON・CSS・JS）は圧縮効率が非常に高いです。

```
例：1MB の JSON
→ gzip 圧縮後：約 100KB（90% 削減）
→ Brotli 圧縮後：約 80KB（92% 削減）
```

サーバーは圧縮してボディを送り、使った圧縮形式を `Content-Encoding` で示します。

```http
HTTP/1.1 200 OK
Content-Encoding: gzip
Content-Type: application/json

[gzip 圧縮された JSON データ]
```

---

## 6. Accept-Charset：文字エンコーディングのネゴシエーション

文字エンコーディング（UTF-8 など）を指定します。

```http
Accept-Charset: UTF-8, ISO-8859-1;q=0.7
```

現代では UTF-8 が事実上の標準となっているため、
このヘッダーを送るブラウザはほとんどありません。

---

## 7. Vary ヘッダー：キャッシュとコンテントネゴシエーション

コンテントネゴシエーションとキャッシュを組み合わせるときに重要です。

同じ URI でも、Accept-Language によって返すコンテンツが違います。
このとき、キャッシュが Accept-Language を考慮せずに返してしまうと問題が起きます。

```
Aさん（日本語希望） → /about → キャッシュが日本語版を保存
Bさん（英語希望）   → /about → キャッシュが間違えて日本語版を返してしまう！
```

`Vary` ヘッダーは、**どのヘッダーによってレスポンスが変わるか** をキャッシュに教えます。

```http
HTTP/1.1 200 OK
Vary: Accept-Language
Content-Language: ja

日本語コンテンツ
```

このレスポンスを見たキャッシュは、
「Accept-Language が違うリクエストには、このキャッシュを使ってはいけない」
と理解します。

```http
Vary: Accept-Encoding     → 圧縮形式が違えば別キャッシュ
Vary: Accept-Language     → 言語が違えば別キャッシュ
Vary: Accept              → メディアタイプが違えば別キャッシュ
Vary: Accept-Encoding, Accept-Language   → 複数指定可
```

## 8. 実践：API でのコンテントネゴシエーション

```http
→ GET /api/users/42 HTTP/1.1
   Host: api.example.com
   Accept: application/json
   Accept-Language: ja

← HTTP/1.1 200 OK
   Content-Type: application/json; charset=UTF-8
   Content-Language: ja
   Vary: Accept, Accept-Language

   {"id": 42, "name": "松尾 一輝", "message": "ようこそ"}
```

```http
→ GET /api/users/42 HTTP/1.1
   Host: api.example.com
   Accept: text/html
   Accept-Language: en

← HTTP/1.1 200 OK
   Content-Type: text/html; charset=UTF-8
   Content-Language: en
   Vary: Accept, Accept-Language

   <html><body><h1>Kazuki Matsuo</h1><p>Welcome</p></body></html>
```

## まとめ

| ヘッダー | 役割 | 対応するレスポンスヘッダー |
|---------|------|------------------------|
| `Accept` | メディアタイプの希望 | `Content-Type` |
| `Accept-Language` | 言語の希望 | `Content-Language` |
| `Accept-Encoding` | 圧縮形式の希望 | `Content-Encoding` |
| `Accept-Charset` | 文字エンコーディングの希望 | `Content-Type`（charset）|

- 同じ URI で異なる表現を返せる（リソースと表現の分離）
- `q=` で優先度を指定できる（0〜1、省略時は 1.0）
- `Vary` ヘッダーでキャッシュにネゴシエーション情報を伝える
- 対応した表現がない場合は `406 Not Acceptable` を返す
