# 第3章-01：HTTP の基礎

---

## 1. HTTP とは

HTTP（HyperText Transfer Protocol）は、クライアントとサーバーが
**リソースをやり取りするための通信プロトコル** です。

1991年に HTTP/0.9 が登場し、現在は HTTP/3 まで進化しています。

---

## 2. HTTP のバージョン

### HTTP/0.9（1991年）

最初の HTTP です。GET メソッドだけを持ち、HTML ファイルを取得するだけのシンプルなものでした。

### HTTP/1.0（1996年・RFC 1945）

ヘッダーが追加されました。GET・HEAD・POST の3メソッドが使えるようになりました。
ただし、1リクエストごとに TCP 接続を切断する仕様でした。

### HTTP/1.1（1997年・RFC 2068 → 1999年・RFC 2616）

現在も広く使われているバージョンです。

主な追加機能：
- **持続的接続（Keep-Alive）**：1つの TCP 接続で複数リクエストを処理
- **パイプライン**：レスポンスを待たずに複数リクエストを送信
- **チャンク転送**：大きなデータを分割して送信
- **Host ヘッダー必須化**：1つのサーバーで複数ドメインをホスト可能に

### HTTP/2（2015年・RFC 7540）

パフォーマンス改善が主眼のバージョンです。

主な特徴：
- **バイナリ形式**：テキストではなくバイナリで通信（処理が高速）
- **多重化**：1つの TCP 接続で複数リクエストを並列処理
- **ヘッダー圧縮（HPACK）**：重複するヘッダーを圧縮
- **サーバープッシュ**：クライアントのリクエスト前にサーバーからデータを送る

### HTTP/3（2022年・RFC 9114）

TCP の代わりに **QUIC（UDP ベース）** を使うバージョンです。

主な特徴：
- **QUIC ベース**：UDP を使うことで TCP の遅延（ヘッドオブラインブロッキング）を解消
- **接続確立が高速**：TLS と接続確立を同時に行う（0-RTT/1-RTT）
- **接続の移行**：Wi-Fi から 4G に切り替わっても接続が維持される

## 3. HTTP の基本：リクエストとレスポンス

HTTP の通信は「リクエスト（要求）」と「レスポンス（応答）」のペアで成り立ちます。

### リクエストの構造

```
リクエストライン
HTTPヘッダー（複数行）
空行
ボディ（オプション）
```

実際の例：

```http
GET /users/42 HTTP/1.1
Host: api.example.com
Accept: application/json
Authorization: Bearer eyJhbGciOiJSUzI1NiJ9...

```

### レスポンスの構造

```
ステータスライン
HTTPヘッダー（複数行）
空行
ボディ（オプション）
```

実際の例：

```http
HTTP/1.1 200 OK
Content-Type: application/json
Content-Length: 52
Date: Mon, 21 Apr 2026 10:00:00 GMT

{"id": 42, "name": "Kazuki Matsuo", "age": 21}
```

---

## 4. リクエストラインの詳細

```
GET /users/42 HTTP/1.1
│   │         │
│   │         └── HTTP バージョン
│   └── リクエスト URI（パス）
└── HTTP メソッド
```

---

## 5. ステータスラインの詳細

```
HTTP/1.1 200 OK
│        │   │
│        │   └── ステータスフレーズ（テキスト説明）
│        └── ステータスコード（3桁の数字）
└── HTTP バージョン
```

---

## 6. TCP/IP との関係

HTTP は TCP/IP の上に成り立ちます。

```
アプリケーション層  HTTP
トランスポート層    TCP
インターネット層    IP
リンク層           Ethernet など
```

HTTP は TCP コネクション上でテキストメッセージを送受信します。
TCP がデータの確実な転送を保証するため、HTTP はその部分を気にしなくてよいです。

### HTTP 通信の流れ

```
① クライアントが TCP コネクションを確立
   （3ウェイハンドシェイク: SYN → SYN-ACK → ACK）

② クライアントが HTTP リクエストを送信

③ サーバーが HTTP レスポンスを返す

④ TCP コネクションを切断（HTTP/1.0）
   または次のリクエストを待機（HTTP/1.1 の Keep-Alive）
```

---

## 7. ステートレスとは

HTTP は **ステートレス（Stateless）** なプロトコルです。
サーバーは各リクエストを独立したものとして処理し、
前回のリクエストのことを覚えていません。

```
リクエスト1: GET /users/42
→ サーバー: 処理してレスポンス返す

リクエスト2: GET /orders/7
→ サーバー: リクエスト1のことは知らない。独立して処理
```

### なぜステートレスか

- **スケーラビリティ**：どのサーバーがリクエストを処理しても結果が同じ
- **シンプルさ**：サーバーがセッション状態を管理する必要がない
- **障害耐性**：サーバーが落ちて別のサーバーに振られても問題ない

### ステートレスの課題

ログイン状態・ショッピングカートの中身など、
「状態」を管理したい場合はどうするか？

→ Cookie やトークンを使って、クライアントが毎回状態情報をサーバーに送ります。
HTTP 自体はステートレスのまま、アプリケーション層でセッション管理をします。

---

## 8. HTTP の通信を実際に見る

`curl` コマンドで HTTP 通信を確認できます。

```bash
# GET リクエストを送って詳細を表示
curl -v https://example.com/

# リクエストとレスポンスのヘッダーだけ表示
curl -I https://example.com/

# POST リクエストを送る（JSON ボディ付き）
curl -X POST https://api.example.com/users \
     -H "Content-Type: application/json" \
     -d '{"name": "Kazuki", "age": 21}'
```

また、ブラウザの開発者ツール（F12）の「Network」タブでも、
実際の HTTP 通信を確認できます。

---

## まとめ

- HTTP はクライアント・サーバー間でリソースをやり取りするプロトコル
- リクエスト（方法・URI・バージョン・ヘッダー・ボディ）を送り、レスポンス（ステータス・ヘッダー・ボディ）を受け取る
- HTTP/1.1 → HTTP/2 → HTTP/3 と進化し、主にパフォーマンスが改善されてきた
- HTTP は TCP/IP の上で動く
- HTTP はステートレス。状態管理はアプリケーション層で行う
