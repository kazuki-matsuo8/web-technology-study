# 第3章-03：ステータスコード

---

## 1. ステータスコードとは

HTTP レスポンスの先頭にある3桁の数字で、
サーバーがリクエストをどのように処理したかを表します。

```http
HTTP/1.1 200 OK
         ↑
     ステータスコード
```

3桁の最初の数字がカテゴリーを表します。

| 1xx | 情報 | リクエストを受け取り、処理中 |
|-----|------|--------------------------|
| 2xx | 成功 | リクエストを正常に処理した |
| 3xx | リダイレクト | 別の URI へ移動が必要 |
| 4xx | クライアントエラー | リクエスト側に問題あり |
| 5xx | サーバーエラー | サーバー側に問題あり |

---

## 2. 1xx：情報

### 100 Continue

クライアントが大きなリクエストボディを送る前に、
サーバーに「続けてよいか」確認する場合に使います。

```http
→ Expect: 100-continue ヘッダー付きリクエスト
← HTTP/1.1 100 Continue
→ 本体のリクエストボディを送信
```

### 101 Switching Protocols

WebSocket へのアップグレードなど、プロトコルを切り替える際に返されます。

```http
→ GET / HTTP/1.1
  Upgrade: websocket

← HTTP/1.1 101 Switching Protocols
  Upgrade: websocket
```

## 3. 2xx：成功

### 200 OK

最もよく使われる成功コードです。リクエストが正常に処理されました。

```http
HTTP/1.1 200 OK
Content-Type: application/json

{"id": 42, "name": "Kazuki"}
```

### 201 Created

リソースが **新規作成** されました。POST リクエストの成功時に使います。
`Location` ヘッダーで作成されたリソースの URI を返すのが一般的です。

```http
HTTP/1.1 201 Created
Location: /users/42
Content-Type: application/json

{"id": 42, "name": "Kazuki"}
```

### 204 No Content

処理は成功したが、**レスポンスボディがない** 場合に使います。
DELETE や PATCH の成功時によく使われます。

```http
HTTP/1.1 204 No Content
```

### 206 Partial Content

リソースの一部分だけを返す場合に使います。
大きなファイルの分割ダウンロード（レンジリクエスト）で使われます。

```http
→ Range: bytes=0-1023
← HTTP/1.1 206 Partial Content
   Content-Range: bytes 0-1023/10240
```

## 4. 3xx：リダイレクト

### 301 Moved Permanently（永久リダイレクト）

リソースが **永久に** 別の URI に移動しました。
検索エンジンは新しい URI に評価を引き継ぎます。

```http
HTTP/1.1 301 Moved Permanently
Location: https://example.com/new-path
```

URI の変更（クール URI の原則上は避けるべきですが）や、
HTTP から HTTPS へのリダイレクトによく使われます。

### 302 Found（一時的なリダイレクト）

リソースが **一時的に** 別の URI にあります。
検索エンジンは元の URI の評価を維持します。

```http
HTTP/1.1 302 Found
Location: https://example.com/maintenance
```

メンテナンスページへの一時的な誘導などに使います。

### 303 See Other

POST・PUT・DELETE 処理後に、**結果を GET で取得すべき URI** を示します。

```http
POST /orders → 注文を作成
← HTTP/1.1 303 See Other
   Location: /orders/100

GET /orders/100 → 作成した注文の詳細を取得
```

フォーム送信後にリダイレクトする「PRG（Post/Redirect/Get）パターン」で重要です。
このパターンにより、ブラウザの「戻る」「再読み込み」で二重送信を防げます。

### 304 Not Modified

キャッシュを使えることを示します。
クライアントが `If-None-Match` または `If-Modified-Since` ヘッダーを送り、
サーバーが「変更なし」と判断した場合に返します。

```http
→ GET /logo.png
   If-None-Match: "abc123"

← HTTP/1.1 304 Not Modified
  （ボディなし。クライアントはキャッシュを使う）
```

### 307 Temporary Redirect

302 と似ていますが、**元のメソッドを維持** してリダイレクトします。
（302 は POST が GET に変わることがあるが、307 は POST のまま）

### 308 Permanent Redirect

301 と似ていますが、**元のメソッドを維持** して永久リダイレクトします。

## 5. 4xx：クライアントエラー

クライアント（リクエスト）側に問題があります。

### 400 Bad Request

リクエストの形式が不正です。
必須パラメーターが欠けている、JSON の形式が壊れているなど。

```http
HTTP/1.1 400 Bad Request
Content-Type: application/json

{"error": "name フィールドは必須です"}
```

### 401 Unauthorized

**認証が必要** です（名前は Unauthorized ですが実際は認証エラー）。
ログインが必要なリソースに未認証でアクセスした場合に返します。

```http
HTTP/1.1 401 Unauthorized
WWW-Authenticate: Bearer realm="api.example.com"
```

### 403 Forbidden

認証はされているが、**権限（認可）がない** 場合です。
ログイン済みだが、そのリソースへのアクセス権がない。

```http
HTTP/1.1 403 Forbidden
Content-Type: application/json

{"error": "このリソースへのアクセス権限がありません"}
```

### 401 vs 403 の違い

| | 意味 | 対処 |
|-|------|------|
| 401 | 誰かわからない | ログインしてください |
| 403 | 誰かはわかるが権限がない | 権限を付与してもらってください |

### 404 Not Found

リソースが **見つかりません**。最も有名なエラーコードです。
URI が存在しない、または削除されたリソースへのアクセス。

```http
HTTP/1.1 404 Not Found
```

なお、存在を知られたくないリソース（管理画面など）に対して
意図的に 404 を返すこともあります（存在自体を隠す）。

### 405 Method Not Allowed

そのメソッドは **許可されていません**。
DELETE が禁止されているリソースに DELETE リクエストを送った場合など。

```http
HTTP/1.1 405 Method Not Allowed
Allow: GET, HEAD
```

### 409 Conflict

**競合** が発生しました。
同じメールアドレスのユーザーが既に存在する場合など。

```http
HTTP/1.1 409 Conflict
Content-Type: application/json

{"error": "このメールアドレスは既に登録されています"}
```

### 410 Gone

リソースが **永久に削除** されました。
404 と違い、「かつてはここにあったが、完全に消えた」ことを示します。

### 422 Unprocessable Entity

リクエストの形式は正しいが、**バリデーションエラー** などで処理できない場合。

```http
HTTP/1.1 422 Unprocessable Entity

{"errors": {"age": ["0以上を入力してください"]}}
```

### 429 Too Many Requests

**レート制限** に達しました。一定時間内のリクエスト数が多すぎます。

```http
HTTP/1.1 429 Too Many Requests
Retry-After: 60

{"error": "リクエスト数の上限を超えました。60秒後に再試行してください"}
```

## 6. 5xx：サーバーエラー

サーバー側に問題があります。クライアントのリクエストは正しいが、
サーバーが処理できない状態です。

### 500 Internal Server Error

サーバーで **予期しないエラー** が発生しました。
コードのバグ、設定ミスなど。

```http
HTTP/1.1 500 Internal Server Error

{"error": "サーバーエラーが発生しました"}
```

詳細なエラー内容をユーザーに見せると情報漏洩になるため、
本番環境では汎用的なメッセージを返します。

### 502 Bad Gateway

**上流サーバーから不正なレスポンス** を受け取りました。
リバースプロキシ（Nginx 等）が、バックエンドサーバーから
おかしなレスポンスを受け取った場合に返します。

### 503 Service Unavailable

サービスが **一時的に利用不可** です。
メンテナンス中、負荷が高すぎる場合など。

```http
HTTP/1.1 503 Service Unavailable
Retry-After: 3600

{"error": "メンテナンス中です。1時間後にお試しください"}
```

### 504 Gateway Timeout

**上流サーバーがタイムアウト** しました。
バックエンドサーバーが時間内に応答しなかった場合。

## 7. ステータスコード選択の指針

```
成功:
- データを返す      → 200 OK
- 作成した         → 201 Created
- 返すものがない    → 204 No Content

リダイレクト:
- 永久に移動       → 301 Moved Permanently
- 一時的に移動     → 302 Found
- POST 後の参照先  → 303 See Other
- キャッシュ有効   → 304 Not Modified

クライアントエラー:
- 形式が壊れている   → 400 Bad Request
- 未ログイン        → 401 Unauthorized
- 権限なし          → 403 Forbidden
- 見つからない      → 404 Not Found
- バリデーションNG  → 422 Unprocessable Entity
- レート制限        → 429 Too Many Requests

サーバーエラー:
- バグ・予期しないエラー → 500 Internal Server Error
- メンテナンス中         → 503 Service Unavailable
```

---

## まとめ

- 1xx：情報（処理中）
- 2xx：成功（200 OK / 201 Created / 204 No Content が頻出）
- 3xx：リダイレクト（301 永久 / 302 一時 / 303 PRG パターン / 304 キャッシュ）
- 4xx：クライアントエラー（400 形式不正 / 401 未認証 / 403 権限なし / 404 見つからない）
- 5xx：サーバーエラー（500 バグ / 503 メンテ / 504 タイムアウト）
