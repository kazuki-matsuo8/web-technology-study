# 第2章-01：URI とは何か

---

## 1. URI の定義

URI（Uniform Resource Identifier）は、Web 上のリソースを **一意に識別する文字列** です。

| 単語 | 意味 |
|------|------|
| Uniform | 統一された形式で |
| Resource | リソース（情報）を |
| Identifier | 識別する |

URI は「Web 上の住所」とよく例えられますが、より正確には **名前** です。
住所は場所を示しますが、URI はリソースの場所であることも、
リソースの名前であることもあります。

---

## 2. URI・URL・URN の関係

よく混同されるので整理します。

```
URI（Uniform Resource Identifier）── 上位概念
│
├── URL（Uniform Resource Locator）── 場所で識別
│   例: https://example.com/users/42
│
└── URN（Uniform Resource Name）── 名前で識別
    例: urn:isbn:978-4-7741-4204-3
```

### URL（Uniform Resource Locator）
リソースの **場所（Location）** で識別する URI です。
「どのサーバーの、どのパスにあるか」を指定します。

```
https://example.com/users/42
```

### URN（Uniform Resource Name）
リソースの **名前（Name）** で識別する URI です。
場所に依存せずリソースを識別します。
ISBN（書籍番号）が代表例です。

```
urn:isbn:978-4-7741-4204-3
```

「このURNの書籍はこの URL で買える」という対応は別途行います。

### 実用上の扱い

現在、Web で使われる URI のほぼすべては URL です。
日常会話では URL・URI はほぼ同義で使われますが、
仕様や技術文書では URI が正式な用語です。

---

## 3. URI の重要性

### リソースへのアクセスを統一する

URI がなければ、リソースへのアクセス方法がシステムごとにバラバラになります。
URI という統一された識別子があることで、どんなリソースも同じ方法でアクセスできます。

```
HTTP リクエスト:  GET https://api.example.com/users/42
                              ↑
                      これが URI
```

### リンクによる相互接続

HTML の `<a>` タグで URI を指定することで、文書同士がリンクで結ばれます。
この「ハイパーリンク」が Web を「World Wide Web（蜘蛛の巣）」たらしめています。

```html
<a href="https://example.com/about">会社概要へ</a>
```

### ブックマークと共有

URI があることで、特定のリソースをブックマークしたり、
URL を共有して他者に同じリソースを教えたりできます。

「さっき見たページ」を再度開けるのは URI のおかげです。

---

## 4. URI がない世界を想像する

URI の重要性を理解するために、URI がない世界を考えてみましょう。

```
ダメな例（URI なしの世界）:
「うちのシステムにログインして、メニューから商品を選んで、
 ID 100 を検索して表示してください」

→ 他の人に教えるのが大変
→ ブックマークできない
→ 検索エンジンがインデックスできない
```

```
良い例（URI がある世界）:
「https://shop.example.com/products/100 を開いてください」

→ 誰でもすぐアクセスできる
→ ブックマーク可能
→ 検索エンジンがインデックスできる
```

URI があることで、リソースへのアクセスが劇的に簡単になります。

---

## 5. URI の設計はインターフェース設計

URI はシステムの外部に公開される **インターフェース** です。

一度公開した URI を後から変更すると、その URI をリンクしている
すべてのページやブックマークが壊れます（いわゆる「リンク切れ」）。

そのため、URI の設計は慎重に行う必要があります。

```
悪い設計：実装の詳細が URI に漏れる
https://example.com/cgi-bin/user.php?action=show&id=42

良い設計：リソースの名前として意味がある
https://example.com/users/42
```

URI の設計については第2章-03 と第2章-04 で詳しく扱います。

---

## 6. URI とセマンティクス

URI はリソースの意味（セマンティクス）を表すことができます。

```
/users/42          → ID が42のユーザー
/users/42/orders   → ID が42のユーザーの注文一覧
/products          → 商品の一覧
/products/100      → ID が100の商品
```

URI を読むだけで「何のリソースか」が伝わります。
これが **リソース指向** の設計です。

---

## まとめ

- URI はリソースを一意に識別する文字列
- URL は URI の一種で「場所」で識別するもの。Web で主に使われる
- URN は URI の一種で「名前」で識別するもの
- URI があることでリソースへのアクセスが統一・簡単になる
- URI は公開インターフェースなので、設計は慎重に行う必要がある
