# 第1章-02：Web を支える3つの技術

---

## 1. Web の三本柱

Web は次の3つの技術によって成り立っています。

```
URI  ── リソース（情報）の「場所・名前」を示す
HTTP ── リソースを「やり取りする」ための通信ルール
HTML ── リソースの「内容・表現」を記述する
```

この3つはそれぞれ独立した仕様ですが、密接に連携しています。

---

## 2. URI（Uniform Resource Identifier）

### URI とは

URI はリソース（Web 上の情報）を **一意に識別する** ための文字列です。

```
https://example.com/users/123
```

これを見るだけで「どのサーバーの、どのリソースか」がわかります。

### URI の役割：一意な名前をつける

Web 上のすべての情報には URI という「住所」があります。
URI がなければ、どこにアクセスすれば目的の情報が取得できるかわかりません。

URL（Uniform Resource Locator）は URI のサブセットで、リソースの「場所（Location）」を示すものです。
現在は URL と URI はほぼ同義で使われることが多いですが、厳密には URI が上位概念です。

### URI の例

| URI | 指し示すもの |
|-----|-------------|
| `https://example.com/` | example.com のトップページ |
| `https://api.example.com/users/42` | ID が42のユーザーリソース |
| `mailto:user@example.com` | メールアドレス（メールのリソース）|
| `tel:+81-90-1234-5678` | 電話番号 |

URI は Web に限らず、あらゆるリソースを識別できる汎用的な仕組みです。

---

## 3. HTTP（HyperText Transfer Protocol）

### HTTP とは

HTTP はクライアント（ブラウザなど）とサーバーが **リソースをやり取りするための通信規約（プロトコル）** です。

「プロトコル」とは「取り決め・手続きのルール」のことです。
HTTP では「こういう形式でリクエストを送ったら、こういう形式でレスポンスを返す」という
ルールが定められています。

### HTTP の基本的なやり取り

```
クライアント                      サーバー
   |                                |
   |  GET /users/42 HTTP/1.1        |
   |  Host: api.example.com         |
   |  ──────────────────────────>   |
   |                                |
   |  HTTP/1.1 200 OK               |
   |  Content-Type: application/json|
   |                                |
   |  {"id": 42, "name": "Kazuki"}  |
   |  <──────────────────────────   |
   |                                |
```

クライアントが「リクエスト」を送り、サーバーが「レスポンス」を返す。
この単純なやり取りが Web の基本です。

### HTTP の特徴

**ステートレス（無状態）**
HTTP は各リクエストを独立したものとして扱います。
前のリクエストの情報を次のリクエストに引き継ぎません。
これにより、サーバーの設計がシンプルになります。

**テキストベース**
HTTP のメッセージは人間が読めるテキスト形式です。
デバッグがしやすいという利点があります。

**汎用性**
HTML だけでなく、画像・動画・JSON・PDF など、あらゆるデータを転送できます。

---

## 4. HTML（HyperText Markup Language）

### HTML とは

HTML はリソースの **内容と構造を記述する** ためのマークアップ言語です。

```html
<!DOCTYPE html>
<html lang="ja">
  <head>
    <title>サンプルページ</title>
  </head>
  <body>
    <h1>こんにちは</h1>
    <p>これは <a href="https://example.com/">リンク</a> です。</p>
  </body>
</html>
```

### ハイパーテキストとは

HTML の "HyperText" は、**文書同士がリンクで結びついている** ことを意味します。
`<a>` タグで別の URI を参照することで、文書間を自由に行き来できます。

これが Web を「World Wide Web（世界的な蜘蛛の巣）」と呼ぶ理由です。
地球規模で文書がリンクされ、網の目のように繋がっています。

### HTML の役割

HTML はリソースの「表現（Representation）」の一形式です。
同じリソースを JSON で表現することも、XML で表現することもできます。
HTML はその中でも「人間がブラウザで読むための表現」に特化しています。

---

## 5. 3つの技術の連携

実際にブラウザで Web ページを表示するとき、3つの技術が連携しています。

```
① ユーザーがブラウザに URI を入力
   → https://example.com/index.html

② ブラウザが HTTP でサーバーにリクエストを送る
   → GET /index.html HTTP/1.1
      Host: example.com

③ サーバーが HTTP で HTML を返す
   → HTTP/1.1 200 OK
      Content-Type: text/html
      <html>...</html>

④ ブラウザが HTML を解析して画面に表示する
```

URI でリソースを指定し、HTTP でリソースを取得し、HTML でリソースを表示する。
この流れが Web の基本サイクルです。

---

## 6. Web の本質：リソース指向

Web が革新的だった理由は、情報を「リソース」という概念で統一したことです。

従来のシステムでは、データベースのレコードや、ファイルシステムのファイルなど、
情報へのアクセス方法がシステムごとにバラバラでした。

Web では、あらゆる情報を **URI で識別可能なリソース** として統一しました。
そして HTTP という共通のプロトコルでアクセスします。

この統一されたインターフェースが、Web の相互運用性と拡張性を生み出しています。

---

## まとめ

| 技術 | 役割 | キーワード |
|------|------|-----------|
| URI | リソースを一意に識別する | 住所、名前 |
| HTTP | リソースをやり取りする | プロトコル、リクエスト、レスポンス |
| HTML | リソースの内容を記述する | ハイパーテキスト、マークアップ |

Web はこの3つが組み合わさることで機能します。
どれか一つが欠けても Web は成り立ちません。
